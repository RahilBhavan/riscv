01 / REPRESENTATIONBUILD NOTES

A bit pattern needs an interpretation

A bit holds 0 or 1. A byte contains eight bits. A 32-bit word contains four bytes. Binary positions carry powers of two, with the least significant bit at position zero.

Hexadecimal uses one digit per four bits. This makes a 32-bit instruction readable as eight hex digits. The prefix 0x means hexadecimal.

Worked example

0x2D = 0010 1101₂ = 32 + 8 + 4 + 1 = 45.

Bitwise AND keeps positions where both inputs have a 1. OR keeps positions where either input has a 1. XOR keeps positions that differ. These operations act on each bit separately.

A multiplexer, or mux, selects one input value. Forwarding uses muxes to choose between register values and newer pipeline results.

01 / REPRESENTATIONBUILD NOTES

Signed arithmetic reuses the same bits

An unsigned byte spans 0 through 255. A signed two's-complement byte spans −128 through 127. For an n-bit value with its top bit set, subtract 2ⁿ from its unsigned value.

Worked example

0xFF is 255 unsigned, but 255 − 256 = −1 signed. 0x80 is 128 unsigned, but −128 signed.

Sign extension copies the sign bit into new upper positions. Extending signed 0x80 to 32 bits gives 0xFFFFFF80. Zero extension gives 0x00000080.

A logical right shift inserts zeros. An arithmetic right shift copies the sign bit. RV32I uses SRL for the first and SRA for the second. Signed comparisons interpret the sign bit. Unsigned comparisons treat every bit as magnitude.

Integer addition wraps modulo 2³² in this core. 0xFFFFFFFF + 1 gives zero. Ordinary ADD does not raise an overflow trap.

02 / DIGITAL HARDWAREBUILD NOTES

A clock edge separates old state from new state

Combinational logic computes outputs from current inputs. An adder, comparator or mux is combinational. A register stores bits across time. It updates at an active clock edge.

Between edges, signals travel through logic and wires. Before the next edge, the destination register needs a stable input. A path that takes too long limits clock frequency.

Worked example

With a 20 ns clock period, the nominal frequency is 1 / 20 ns = 50 MHz. The useful combinational budget is smaller because registers require setup time and clocks have uncertainty.

A pipeline puts registers between work regions. It overlaps different instructions across those regions. It does not make one addition logically need fewer steps.

The actual core uses a synchronous, active-high reset. Reset takes effect on a rising edge. It clears pipeline valid bits and sets the program counter to zero.

02 / DIGITAL HARDWAREBUILD NOTES

RTL describes concurrent hardware

Register-transfer level, or RTL, describes stored state and the logic between registers. Verilog source order is not a CPU instruction schedule. Separate hardware blocks operate concurrently.

always @(posedge clk) begin
    if (reset) begin a <= 0; b <= 0; end
    else begin a <= input_value; b <= a; end
end

Nonblocking assignments (<=) schedule state changes after the block evaluates. Here, b receives the old a. That behavior creates a pipeline boundary.

always @* begin
    result = 0;
    case (select)
        0: result = a + b;
        1: result = a ^ b;
        default: result = 0;
    endcase
end

Blocking assignments (=) are appropriate for this combinational calculation. Give outputs defaults so every path defines a value. A missing assignment can infer a latch, an unintended storage element.

03 / THE INSTRUCTION CONTRACTBUILD NOTES

The ISA defines visible behavior

An instruction set architecture, or ISA, defines the operations software can request and the state it can observe. A microarchitecture chooses how to execute those requests.

RV32I is the RISC-V base integer instruction set with 32-bit integer registers. The integer register file has x0 through x31. x0 always reads zero and discards writes. The program counter, or PC, identifies the instruction address.

add x3, x1, x2 means read x1 and x2, add their 32-bit values, and write x3. addi x1, x0, 7 uses an immediate constant encoded inside the instruction.

RISC-V separates register arithmetic from memory access. lw x1, 128(x0) loads a word from byte address 128. sw x1, 132(x0) stores a word at byte address 132.

Same contract, different execution

A single-cycle machine and a five-stage pipeline should produce the same architectural instruction results. Their timing and internal state differ.

lw x4, 128(x0)base 0, offset 128x4 = memory word

03 / THE INSTRUCTION CONTRACTBUILD NOTES

An instruction word names operands and work

RV32I instructions here are 32 bits long. Decode examines fields within that word. The opcode selects a broad instruction class. funct3 and sometimes funct7 refine the operation.

In an R-type arithmetic instruction, rd names the destination. rs1 and rs2 name source registers. The bit positions stay fixed across several instruction formats, simplifying decode.

Worked example

add x3, x1, x2 encodes as 0x002081B3. Its opcode is 0x33, funct3 is 0, funct7 is 0, rd is 3, rs1 is 1 and rs2 is 2.

An I-type instruction uses bits 31:20 for a 12-bit immediate. addi x1, x0, 7 encodes as 0x00700093. Ordinary arithmetic immediates are sign-extended. Shift immediates have additional encoding rules.

The local tests construct words with Python encoders. A standard assembler is useful later, but is not required to run these regressions.

04 / THE DATAPATHBUILD NOTES

One instruction moves through a datapath

A datapath carries values through hardware. A control decoder selects the operation, input muxes and permitted side effects. The ALU, or arithmetic logic unit, computes integer arithmetic and bitwise results.

For add x3, x1, x2, fetch obtains the instruction, decode identifies the registers, the register file supplies operands, and the ALU adds them. A write-enable permits the result to update x3.

A load instead uses the ALU to add the base register and immediate offset. Data memory supplies the final value. A store uses the calculated address plus a separate store-data operand.

A single-cycle implementation completes this path within one clock period. A long path through instruction memory, decode, registers, ALU and data memory can force a long clock.

Control and data must refer to the same instruction. If a pipeline carries a result but loses its destination or write-enable, the value can update the wrong state.

04 / THE DATAPATHBUILD NOTES

Addresses count bytes

A word contains four bytes. In little-endian order, the least significant byte sits at the lowest address. Alignment requires a word address divisible by four and a halfword address divisible by two in this core.

Worked example

Storing 0x80FF007F at address 128 writes bytes 7F, 00, FF and 80 at addresses 128, 129, 130 and 131.

lb x1, 131(x0) returns 0xFFFFFF80. lbu x1, 131(x0) returns 0x00000080. The memory byte is identical. The load operation selects sign or zero extension.

The core exposes an aligned data word address plus four byte-write strobes. It uses the low effective-address bits to select a byte or halfword. Misaligned halfword and word accesses produce a local trap.

Instruction and data memories are separate. Both reads must be combinational. There is no ready signal or support for waiting on a slow memory.

05 / FIVE STAGESBUILD NOTES

Different instructions share the machine over time

The five stages are instruction fetch (IF), instruction decode (ID), execute (EX), memory access (MEM) and writeback (WB). Each stage performs different work on a different instruction during the same clock interval.

Registers between stages preserve each instruction's state. A valid bit says whether a stage contains an actual instruction. An invalid entry is a bubble. A bubble must never update architectural registers or memory.

In the RTL, f_* is the IF/ID register and feeds ID. x_* feeds EX, m_* feeds MEM and w_* feeds WB. The name prefix describes stored state, not an additional stage. The fetch PC can be ahead of WB. Each instruction carries its own saved PC.

Ideal timing

For N independent instructions, an ideal five-stage pipeline completes the last WB in N + 4 cycles, counting initial fill and no stalls. For large N, throughput approaches one retired instruction per cycle.

One instruction still crosses all five stages. Pipeline throughput and instruction latency answer different questions.

06 / DEPENDENCIESBUILD NOTES

A younger instruction can need an unfinished result

A data dependency exists when one instruction uses a result produced by another. A pipeline creates a timing problem if the consumer needs that value before normal writeback supplies it.

addi x1, x0, 7
add  x2, x1, x1

The ADD needs x1 in EX while the ADDI result has not yet reached WB. Reading the old register file value would give the wrong answer.

Forwarding, also called bypassing, routes an available result directly to the consumer. A stall waits when a required value does not exist yet. A flush discards work that should no longer execute, such as a wrong-path instruction.

The classic categories are data hazards, control hazards and structural hazards. This design avoids a shared instruction/data memory-port conflict by using separate ports. A single shared port would require arbitration or stalls.

Dependency is about meaning. Hazard handling is about when the machine can deliver the required value.

MechanismPurposeExample
ForwardUse an already computed resultALU result into next ALU
StallWait for a required valueImmediate load consumer
FlushDiscard younger wrong-path workTaken branch resolved in EX

06 / DEPENDENCIESBUILD NOTES

Forwarding selects the newest available value

Each EX input can come from its saved ID operand, a WB result, or a newer non-load result in MEM. The hardware compares destination and source register numbers.

value = saved_operand
if WB is a valid matching writer: value = WB.result
if MEM is a valid matching non-load writer:
    value = MEM.result

The last matching assignment wins in this combinational calculation. MEM represents a younger producer than WB, so its value has priority. x0 never participates as a producer.

Worked example

If an older instruction writes x1=5 and a newer instruction writes x1=8, a following consumer must use 8. Keeping the WB value when a newer MEM result matches would be wrong.

The same source selection feeds store data, branch comparisons, JALR bases and DOT4. Checking only ordinary ADD operands leaves important hazards unresolved.

06 / DEPENDENCIESBUILD NOTES

Writeback and decode can meet on one edge

The register file writes at a rising edge. ID/EX also captures its inputs at that edge. With nonblocking assignments, a register-file read expression can still see the old value during evaluation.

addi x1, x0, 7
addi x8, x0, 1
addi x9, x0, 2
add  x2, x1, x1

When the ADD reaches ID, the first ADDI is in WB. The core explicitly bypasses the WB value into the captured ID operand if the source register matches.

This WB-to-ID bypass solves a different timing boundary from the EX operand forwarding muxes. Both can matter in the same implementation.

A good test varies dependency distance. Adjacent instructions exercise one path. Two intervening instructions can exercise another. Also vary whether the dependency appears on rs1, rs2 or both.

For a store, distinguish the address base from the stored value. They are separate dependencies even though both use the same register file.

07 / THE LOAD-USE STALLBUILD NOTES

A load address is not the loaded value

lw  x1, 0(x0)
add x2, x1, x1

The load calculates its address in EX. Its data becomes available during MEM and is captured into MEM/WB. When the following ADD would enter EX, that loaded value is not yet available through this core's forwarding paths.

The interlock holds PC and IF/ID for one cycle, inserts an invalid EX entry and lets the older load advance. On the next cycle, the ADD enters EX and receives the loaded value from WB.

The hazard detector checks whether the ID instruction really uses rs1 or rs2. Bits in an immediate can occupy the rs2 field position without naming a source register. Treating those bits as a dependency causes unnecessary stalls.

This is a one-cycle stall only under the chosen memory and forwarding contract. A slower memory needs a different protocol and possibly more waiting.

07 / THE LOAD-USE STALLBUILD NOTES

One bubble preserves the instruction order

The table counts clock intervals. Stage values are visible during each interval and move at its ending edge. “Held” means the instruction stays in its current front-end position.

At the end of cycle 3, the hazard freezes the front end. The load reaches MEM in cycle 4 while EX holds a bubble. In cycle 5, WB forwards the loaded value to ADD in EX.

In cycle 6, the ADD result in MEM forwards into the store's EX operand selection. The store changes memory at the end of cycle 7 and emits its retirement record after WB in cycle 8.

A memory side effect and the later retirement notification occur at different pipeline points. The checker verifies the ordered byte-write stream as well as retirement records.

08 / CONTROL FLOWBUILD NOTES

A taken branch discards two younger stages

beq x1, x1, target
sw  x2, 128(x0)      # wrong path
addi x3, x0, 99      # wrong path
target: addi x4, x0, 42

The branch decides in EX. At that point, younger instructions occupy ID and IF. A taken branch invalidates both. Fetch resumes at the target on the following cycle.

With no other stalls, this design pays two lost issue opportunities for an EX redirect. An untaken branch continues sequential fetching. Other pipelines can resolve branches later and incur a different penalty.

JAL writes a return address and redirects using a PC-relative immediate. JALR adds a signed immediate to a register base and clears target bit zero. This core traps if the resulting taken target is not word aligned.

Forwarded operands must feed branch comparisons and JALR bases. Otherwise a correct arithmetic pipeline can still choose the wrong instruction path.

08 / CONTROL FLOWBUILD NOTES

A trap halts this execution environment

A trap reports an exceptional event. Here, ECALL, EBREAK, unsupported instructions and misaligned accesses or taken targets emit a local trap record and halt fetch.

The faulting instruction performs no register or memory side effect. Younger instructions are discarded. Older instructions continue through the remaining stages. Reset starts execution again.

This is a small teaching environment. It has no trap vector, privilege state, cause register, interrupt mechanism or recovery handler. The core also has no memory access-fault response.

FENCE orders memory operations architecturally. The supported base FENCE acts as a no-op under the stated single-hart, ordered, fixed-latency memory contract. FENCE.I and CSRs are absent.

A Harvard interface uses separate instruction and data ports. This core additionally assumes combinational reads. FPGA block RAM usually has synchronous reads, so connecting typical block RAM directly changes the timing contract.

An instruction implementation is always interpreted within an execution environment. Documenting that environment prevents a small core from appearing more complete than it is.

09 / CUSTOM COMPUTEBUILD NOTES

DOT4 multiplies four signed byte pairs

The custom instruction treats each source register as four independent signed 8-bit lanes. Lane zero is the least significant byte. It multiplies corresponding lanes and sums all four products into a 32-bit result.

DOT4 rd, rs1, rs2
rd = sum(signed8(rs1.byte[i]) * signed8(rs2.byte[i]))
     for i = 0, 1, 2, 3

There is no accumulator input, rounding or saturation. The sum ranges from −65024 to 65536. A signed 16-bit result is too narrow. A signed 18-bit value can represent the full range, and the destination remains 32 bits.

The encoding uses custom-0: opcode 0x0B, funct3=0 and funct7=0. Other function combinations trap. GNU assembly can emit .insn r 0x0b, 0, 0, a0, a1, a2.

This project-specific instruction illustrates a small hardware/software tradeoff. It is not a ratified vector extension or evidence of a lab's accelerator architecture.

For illustrative source words A=0x0102FF80 and B=0x020304FF, decode each byte as signed before multiplying.

The sum is 128 − 4 + 6 + 2 = 132. The byte 0x80 means −128 here, and 0xFF means −1. Reading the whole word as one signed integer does not implement lane-wise arithmetic.

Four lanes of −128 multiplied by −128 produce 4 × 16384 = 65536. Four lanes of −128 multiplied by 127 produce 4 × (−16256) = −65024.

10 / READING THE ACTUAL COREBUILD NOTES

The RTL has four useful reading passes

Pass 1: stored state

Find regs, pc and each stage's valid bit. Follow PC, instruction, destination and write-enable through the pipeline registers.

Pass 2: operand selection and execution

Read the first combinational block for forwarding. Read the opcode case for execution. Notice default control values, legality checks, address generation and the signed DOT4 expression.

Pass 3: hazard and memory boundaries

Find uses_rs1, uses_rs2, hazard, redirect and fault. Then follow byte strobes, aligned addresses and load extension.

Pass 4: the rising edge

Read reset first. Then follow WB, MEM/WB and EX/MEM updates. Finally inspect the redirect/fault, hazard and ordinary-advance cases. Older stages advance even when the front end stalls.

Where to start

rtl/rv32_core.sv contains the core. tests/tb.sv supplies clocks and memory. tests/run.py supplies programs and expected results. rtl/timing_top.sv supplies the implementation measurement shell.

11 / VERIFICATIONBUILD NOTES

A reference model predicts architectural results

A sequential model executes one instruction at a time without implementing the pipeline. For each instruction, it calculates the next PC, destination register, result and trap behavior.

The regression runs the same machine words through that model and the RTL. It compares each retired PC, instruction, destination, value and trap flag. It separately compares every ordered byte write.

This catches errors that a final signature can hide. A wrong-path store might briefly corrupt memory and later be overwritten. A final register check alone can miss it.

The model uses Python integers and explicit 32-bit masking. Signed conversion is deliberate. Python's unlimited integer width does not automatically behave like a 32-bit register.

Both model and RTL belong to this project. Independent code does not guarantee an independent interpretation of the ISA. Hand-calculated examples, external models, ACT4 and formal properties provide additional evidence.

11 / VERIFICATIONBUILD NOTES

Tests should target a reason the core could fail

A directed test constructs a known corner case. A randomized test explores many combinations using a reproducible seed. Both need an expected result.

For forwarding, cross source operand with producer distance and producer type. Test competing writers, x0 and a source field that is actually an immediate. For loads, cover each size, signedness and aligned byte position.

For control flow, check both outcomes of every branch, JAL, JALR, backward loops and wrong-path side effects. For traps, put a store after the fault and prove it never writes.

An assertion checks an invariant during execution. Useful future assertions include x0 stability, no writes from invalid stages, front-end stability on a stall and younger-stage squash on a redirect.

Negative experiment

Predict a failing program, deliberately break one forwarding selection in a separate temporary worktree, and observe the first mismatch. Restore the good implementation. Preserve the failure explanation.

Mid-flight reset tests, formal integration and a complete hazard cross-coverage plan remain follow-up work. Do not describe them as already checked.

12 / IMPLEMENTATION EVIDENCEBUILD NOTES

Synthesis maps logic, routing estimates timing

Synthesis turns RTL into a network of target logic resources. A lookup table, or LUT, implements a small Boolean function. Flip-flops store state. Dedicated RAM and DSP blocks can implement larger memories and arithmetic when the device provides them.

Place-and-route assigns resources to physical locations and connects them. Wire delay matters. A synthesis cell count alone cannot establish a routed clock frequency.

The measurement shell registers instruction/load inputs and folds core outputs into an observable register. It keeps the datapath alive during optimization. It contains no program memory, data memory or peripherals.

Measured reference: iCE40 HX8K CT256, seed 1, requested 12 MHz. The routed internal timing estimate is 34.74 MHz. Mapping uses 3,962 LUT4 primitives and 1,692 flip-flops, packed into 5,554 logic cells.

Package I/O is unconstrained. The result is not external timing sign-off or a measured board clock. HX8K provides no hard DSP blocks, so DOT4 uses logic. FPGA resources are not ASIC area in square millimeters.

12 / IMPLEMENTATION EVIDENCEBUILD NOTES

Clock frequency is only one part of performance

Cycles per instruction, or CPI, divides total cycles by retired instructions. A useful workload also has an instruction count. Execution time is approximately:

time = instruction count × CPI ÷ frequency
Illustrative example

A 100-instruction sequence needs 4 fill cycles, 10 load-use stalls and 16 cycles for eight taken redirects. Total: 130 cycles. CPI: 1.30. At an assumed 20 MHz, that is 6.5 microseconds.

DOT4 can reduce instruction count for packed dot products, but it can also add logic delay. Compare total cycles and each implementation's own clock estimate. Include packing and memory traffic when claiming end-to-end improvement.

RV32I has no integer multiply instruction. A fair scalar RV32I baseline needs a software multiply routine. Compiling a C multiply for RV32IM silently changes the comparison.

No matched scalar-versus-DOT4 kernel benchmark exists in this reference yet. No application speedup or power result has been measured.

A short program becomes a regression

Place this entry inside suite() in tests/run.py. The helpers encode ordinary instruction words. The existing reference model supplies the expected trace and byte writes.

yield 'personal_load_store', [
    imm(0, 1, 0, 9),           # addi x1,x0,9
    store(2, 0, 1, 128),       # sw x1,128(x0)
    imm(2, 2, 0, 128, 3),      # lw x2,128(x0)
    store(2, 0, 2, 132),       # sw x2,132(x0)
    0x00100073,                # ebreak
]

imm(funct3, rd, rs1, immediate, opcode) defaults to opcode 0x13. Passing opcode 3 selects a load. store(funct3, rs1, rs2, offset) uses funct3=2 for a word store.

Predict x1=9, x2=9, memory word 128=9 and memory word 132=9. The immediate load-to-store dependency should create one interlock cycle under the current design.

APPENDIX B / A RUNNABLE TESTBUILD NOTES

The skipped store must never write

This program takes a branch over one store. Branch offsets are relative to the branch instruction's address, in bytes.

yield 'personal_wrong_path', [
    imm(0, 1, 0, 7),           # PC 0: x1=7
    branch(0, 1, 1, 8),        # PC 4: beq to 12
    store(2, 0, 1, 128),       # PC 8: discard
    imm(0, 2, 0, 42),          # PC 12: x2=42
    0x00100073,
]

The retired PC sequence is 0, 4, 12 and 16. No byte-write event should occur. The branch compares x1 against itself, so it takes the branch regardless of x1's value.

For a DOT4 test, use r(0, rd, rs1, rs2, op=0x0b). Load the desired source words first, then follow DOT4 with a consumer of rd. Check the signed-lane calculation by hand.

For the invalid-branch coverage experiment, encode an unsupported funct3, such as branch(2, 0, 0, 8), and put a store immediately after it. The branch should emit a trap and the younger store should never write.

These recipes are additional learning tests. They are not included in the published 144-program baseline counts. After you add them, regenerate your reports and record the new counts.
