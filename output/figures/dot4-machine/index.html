RV32I core, custom-0 extension

DOT4, drawn as a machine

One instruction multiplies four pairs of signed bytes and adds the four products. Change the bytes and follow them through each part.

Figure 1. The DOT4 unit

rs1 and rs2 each hold four signed bytes. Lane i is bits [8i+7:8i]. Each lane has its own multiplier. Two adders sum lanes 0 and 1 and lanes 2 and 3, and a third adds the two partial sums. rd gets the result as a signed 32-bit number. In the RTL the whole unit is combinational in the EX stage, so DOT4 takes one cycle like ADD.

Drag the figure to turn it. See-through shows the bits inside. The bit-product array shows which bit pairs are both 1. It is not the synthesized netlist.

Encoding

dot4 a0, a1, a2 is an R-type instruction in the custom-0 opcode space. GNU as writes it as .insn r 0x0b, 0, 0, a0, a1, a2. Any other funct3 or funct7 under custom-0 traps.

Figure 2. The iCE40-HX8K Breakout Board

Simulated. Not yet run on hardware.

The board image runs the core from block RAM. It loops a self-checking program and shows the verdict on eight LEDs. Run self-test plugs in the USB cable, loads the FPGA and plays what the LEDs would show, following rtl/board_top.sv.

LED0 blinks at its real rate. LED1 and the pass counter assume one instruction per cycle, so they run a little fast. Part placement is simplified. The die map in see-through shows how much logic is used, not where.
